# vibe-check

An AI agent pipeline that explores a live page, grades its own exploration
before trusting it, generates a Playwright test suite from that exploration,
runs it, and fixes its own failures — with a hard rule the agents can't
route around: the agent that writes tests never touches the browser, and
the agent that touches the browser never writes a test.

```
explorer  --(element-map.json + context.md)-->  grader (explore mode)
                                                        |
                                            gate: band >= B, or stop here
                                                        v
writer  --(4-layer pytest+playwright suite)-->  runner  -->  grader (writer mode)
```

## Why two engines, not one

**[Vibium](https://vibium.com)** drives the explorer. Its whole API —
semantic `find(role=..., label=..., text=...)`, an accessibility tree as a
first-class return value, a ~10MB zero-config binary — is built for an LLM
to drive interactively, deciding what to look at next. That's exactly the
explorer's job: reason about an unfamiliar page, not execute a fixed script.

**Playwright** (via `pytest-playwright`) executes the actual suite. Once a
locator strategy has been chosen and graded, running it deterministically,
fast, and repeatably in CI is a solved problem with a decade of tooling
behind it — that's not something you want an LLM re-deciding on every run.

Using Vibium to replace Playwright, or Playwright to replace Vibium, would
throw away exactly the property that makes each one good at its job. This
repo exists to demonstrate that split working end to end, not to pick a
side.

## The rule that makes this trustworthy, not just automated

The writer agent is given `Read`/`Write`/`Glob` tools only — no browser
access, no MCP tools, enforced at the SDK's tool-permission level rather
than by prompt instruction alone. If the explorer's output is wrong,
incomplete, or scores below a `B` band on the 8-dimension rubric in
`agents/grader`, the writer refuses to run rather than guess. This mirrors
what actually breaks test suites in practice: not bad test-writing, but
tests quietly authored against assumptions nobody re-checked against the
live page.

The runner extends the same discipline to failures: every failing test is
classified into one of five causes (`selector_rot`, `assertion_mismatch`,
`timing`, `test_data`, `real_bug`) before anything is touched. Real bugs are
never edited into passing — they're marked `xfail` with a root-cause note.
A green suite that got there by loosening an assertion is worse than a red
one that's honest about what's broken.

## Setup

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1        # or `source .venv/bin/activate` on macOS/Linux
pip install -e .
playwright install chromium
cp .env.example .env              # fill in CLAUDE_CODE_OAUTH_TOKEN or ANTHROPIC_API_KEY
```

Auth: this repo defaults to `CLAUDE_CODE_OAUTH_TOKEN` (run `claude
setup-token`) so it runs against a personal Claude subscription instead of
metered API billing — fine for a single-user local project, not something
to distribute to others (see Anthropic's Agent SDK policy on third-party
`claude.ai` login). Set `ANTHROPIC_API_KEY` instead if you don't have a
subscription token, or if you fork this and want others to bring their own.

## Running the pipeline

```bash
python -m agents.explorer.explorer_agent --page login --path /
python -m agents.grader.grader_agent --mode explore --target login
python -m agents.writer.writer_agent --page login
python -m agents.runner.runner_agent --page login
python -m agents.grader.grader_agent --mode writer --target login
```

Each step is a separate process on purpose — you can inspect
`output/explorer/login/element-map.json` and `explore-grading.json` between
steps, and re-run any single stage without re-running the ones before it.

Target site: [saucedemo.com](https://www.saucedemo.com) — public, stable,
no auth/secrets required, so this is runnable by anyone who clones it.

## Repo layout

```
agents/
  explorer/   Claude Agent SDK + Vibium tools (navigate, find, click, a11y tree, screenshot)
  grader/     scores explorer output (8-dim rubric) and writer output (binary pass/fail) against evals/
  writer/     Read/Write/Glob only -- generates pages/, modules/, fixtures/, specs/ from explorer output
  runner/     runs pytest, classifies + fixes failures, re-verifies, writes a fix-log
  shared/     config + the JSON schemas every agent boundary passes through
evals/        golden, declarative (plain-English) expectations -- no code
tests/        generated BY the writer agent, not hand-authored
.github/workflows/pipeline.yml   explore -> gate -> write -> run -> grade, manual dispatch only
```

## What's deliberately out of scope

No flakiness/quarantine tracking, no dashboard, no contract testing, no
performance/security suites. Those are real, valuable layers in a
production framework — they're cut here so this stays a complete, readable,
end-to-end demonstration of the agent split above, not a partially-built
clone of a much larger system.
